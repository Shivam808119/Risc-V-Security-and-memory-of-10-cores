# Rocket Core: Memory and Security Study

The in-order RISC-V application core from UC Berkeley, generated by the Rocket Chip generator in Chisel. It is the reference "real" RISC-V core and the base for many commercial and academic chips.

Upstream: https://github.com/chipsalliance/rocket-chip, via Chipyard: https://chipyard.readthedocs.io

## Key facts

| Item | Value |
|------|-------|
| Type | In-order pipelined core generator, with L1 instruction and data caches [src] |
| ISA | RV64GC is the typical configuration, RV32 also possible [verify] |
| Pipeline | 5 stages [verify] |
| Language | Chisel (Scala-embedded HDL), SoC elaborated with Diplomacy [src] |
| Bus | TileLink, with adapters to AXI4, AHB-lite, and APB [src] |
| Tile contents | Core, page-table walker, L1 I$, L1 D$, optional RoCC accelerator [src] |
| Higher levels | System bus to L2 cache banks to memory bus to DRAM controller via TileLink-to-AXI converter [src] |
| Swappable | Chipyard lets you replace the Rocket tile with a BOOM tile [src] |

## Why it exists

To be a clean, parameterizable, silicon-proven in-order core that can run Linux, and the generator infrastructure (TileLink, Diplomacy) that lets researchers add accelerators and swap cores.

## Study goals

1. Understand how a tile (core, caches, PTW) connects to a coherent memory system.
2. Learn TileLink and why it is used instead of AXI inside the SoC.
3. Understand the page-table walker, TLB, and PMP in a real design.
4. See how the same infrastructure hosts both Rocket (in-order) and BOOM (out-of-order).

## Hands-on checklist

- [ ] Set up Chipyard, build a Rocket config, simulate with Verilator.
- [ ] Open the generated Verilog and identify the I$, D$, and PTW.
- [ ] Change cache size and associativity in the config and re-run a benchmark.
- [ ] Run `docs/labs/timing_lab.c`, then repeat with the D$ shrunk or disabled to see timing change.
- [ ] Read the Rocket Core and Memory Hierarchy pages in the Chipyard docs.
